# ClassMind.ai — Teacher Face Recognition Module

> Python-based real-time face recognition system for ClassMind.ai smart classroom attendance.

---

## Architecture Overview

```
Browser (React)
    │
    ▼
Node.js Express (port 5003)  ← existing backend
    │   ├── /api/teachers/register-face
    │   ├── /api/attendance/mark
    │   ├── /api/attendance/history
    │   └── /api/attendance/teacher/:id  ← NEW
    │
Python FastAPI (port 8000)   ← NEW microservice
    │   ├── /api/face/upload-photo
    │   ├── /api/face/train
    │   ├── /api/face/recognize
    │   ├── /api/face/scan-webcam
    │   ├── /api/face/register-to-db
    │   └── /api/attendance/teacher/:id (proxies to Node)
    │
MongoDB (ClassMind database)
    │   ├── Teachers      — faceDescriptor: [128 floats]
    │   └── Attendance    — teacherId, classId, confidence, status
```

## Quick Start

### Step 1: Install Python Dependencies

**Option A – face_recognition (dlib-based, more accurate):**
```bash
# Windows: Install build tools first
pip install cmake
pip install dlib
pip install face_recognition
pip install fastapi uvicorn opencv-python pymongo httpx python-dotenv numpy Pillow scipy
```

**Option B – DeepFace/ArcFace (easier to install, no cmake needed):**
```bash
pip install deepface
pip install fastapi uvicorn opencv-python pymongo httpx python-dotenv numpy Pillow
```

> **Tip for Windows**: If `dlib` fails to build, use **Option B** (DeepFace) — it works without any C++ build tools.

---

### Step 2: Prepare Teacher Photos

Create the `dataset/` folder structure:
```
dataset/
├── teacher_1/         ← Teacher with ID = 1 in MongoDB
│   ├── photo1.jpg
│   └── photo2.jpg     (multiple photos = better accuracy)
└── teacher_2/
    └── photo1.jpg
```

**Tips for good photos:**
- Clear, well-lit, front-facing face
- No sunglasses or heavy accessories
- Use 2-5 photos per teacher for best results

---

### Step 3: Train Face Encodings

```bash
cd ClassMind.ai

# Option A (dlib/face_recognition):
python train_encodings.py

# Option B (DeepFace/ArcFace):
python train_encodings_deepface.py
```

Output: `model/face_encodings.pkl` (auto-created)

---

### Step 4: Start the Python FastAPI Server

```bash
cd ClassMind.ai
uvicorn fastapi_server:app --host 0.0.0.0 --port 8000 --reload
```

API Docs (Swagger UI): http://localhost:8000/docs

## Additional Requirements and API Keys

- `GEMINI_API_KEY`: To enable automatic slide summarization (Gemini/GenAI), add your API key to `ClassMind.ai/.env` or the Node backend `server/.env` as `GEMINI_API_KEY=your_key_here`. If this variable is not set the server will fall back to a local mock summary.

- `TensorFlow` / `tf-keras`: Some DeepFace/retinaface integrations require `tf-keras` when running TensorFlow >= 2.20. If you encounter runtime errors mentioning `tf-keras` or compatibility issues, install the following (used in this project):

```bash
pip install tensorflow==2.21.0 tf-keras==2.21.0
```

This resolves known compatibility issues with retinaface on recent TensorFlow releases.

### Step 5: Use the System

**Test Recognition (upload an image):**
```bash
curl -X POST http://localhost:8000/api/face/recognize \
  -F "file=@test_photo.jpg"
```

**Test Webcam Scan:**
```bash
curl -X POST http://localhost:8000/api/face/scan-webcam
```

**Upload Teacher Photo:**
```bash
curl -X POST http://localhost:8000/api/face/upload-photo \
  -F "teacher_id=1" \
  -F "file=@teacher_photo.jpg"
```

**Re-Train After Upload:**
```bash
curl -X POST http://localhost:8000/api/face/train
```

## API Endpoints Reference

### Python FastAPI (port 8000)

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/api/face/health` | Health check + encoding status |
| POST | `/api/face/upload-photo` | Upload teacher photo to dataset |
| POST | `/api/face/train` | Trigger re-training of encodings |
| POST | `/api/face/recognize` | Recognize face from uploaded image |
| POST | `/api/face/scan-webcam` | One-shot webcam scan |
| POST | `/api/face/register-to-db` | Extract encoding + save to MongoDB |
| POST | `/api/attendance/mark` | Mark attendance (proxied to Node.js) |
| GET | `/api/attendance/teacher/{id}` | Attendance history for teacher |

### Lecture & Emotion Endpoints (new)

| Method | Endpoint | Description |
|--------|----------|-------------|
| POST | `/api/lecture/feed-frame` | Send a base64 camera frame during an active lecture. Analyzes emotions and buffers segment readings. |
| POST | `/api/lecture/end` | End the lecture, flush final segment, and compute overall engagement report (proxied to Node backend). |
| GET  | `/api/lecture/{lecture_id}/report` | Fetch final lecture report and per-segment data. |

These endpoints integrate with the Node backend `/api/engagement/*` routes — Python handles frame analysis (DeepFace/OpenCV) and Node persists aggregated segments and updates `Class.analytics`.
### Node.js Express (port 5003) — Enhanced

| Method | Endpoint | Description |
|--------|----------|-------------|
| POST | `/api/teachers/register-face` | Save 128D descriptor to MongoDB |
| GET | `/api/teachers/face-data` | Get all teachers with face data |
| POST | `/api/attendance/mark` | Mark attendance with business rules |
| GET | `/api/attendance/history` | Filtered attendance history |
| GET | `/api/attendance/teacher/:id` | Full teacher attendance report |

## Integration with Existing React Frontend

Your existing **`TeacherAttendanceScanner.jsx`** already works fully with:
- Live webcam feed via `getUserMedia`
- Simulation controls (multiple faces, unknown face, etc.)
- Sends to `/api/attendance/mark` on Node.js

**To integrate real Python recognition** in the React frontend, modify `handleFaceVerification()` in `TeacherAttendanceScanner.jsx`:

```javascript
// Instead of mock confidence, call Python API first:
const pythonRes = await fetch('http://localhost:8000/api/face/scan-webcam', {
    method: 'POST'
});
const recognitionResult = await pythonRes.json();

if (!recognitionResult.matched) {
    setErrorMessage(recognitionResult.message || 'Face not recognized');
    return;
}

// Then mark attendance on Node.js with real confidence
await fetch('/api/attendance/mark', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
        teacherId: recognitionResult.teacher_id,
        classId: courseId,
        lectureId: `LEC-${new Date().toISOString().split('T')[0]}`,
        confidence: recognitionResult.confidence,
        recognitionMethod: 'face_recognition'
    })
});
```

## Business Rules Enforced

| Rule | Where Enforced |
|------|----------------|
| BR-1: Only registered teachers recognized | Node.js: checks `faceDescriptor` exists |
| BR-2: Teacher must be assigned to class | Node.js: checks `assignedClasses` |
| BR-3: No duplicate attendance per lecture | Node.js: MongoDB unique index |
| BR-4: Confidence ≥ 80% | Node.js: `confidence < 0.8` check |
| BR-5: Multiple faces → reject | Python: checks `face_locations > 1` |
| BR-6: Unknown face → reject | Python: distance threshold check |

## Troubleshooting

### `dlib` installation fails on Windows
→ Use **Option B (DeepFace)** — no compilation needed.

### `No face detected` during training  
→ Ensure photos are well-lit, face clearly visible, JPG/PNG format.

### Recognition is slow  
→ Change `model="hog"` to `model="cnn"` for GPU acceleration in `recognize_teacher.py`.

### Python server can't connect to MongoDB  
→ Check `MONGO_URI` in `.env` matches your Node.js server's `.env`.

### React frontend "Network Error"  
→ Ensure Python FastAPI runs on port 8000 and CORS is configured.
